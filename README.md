# Эмулятор командной оболочки (вариант 4)

## 1. Общее описание

Консольный эмулятор оболочки UNIX-подобной ОС на Python 3.10+ (внешних
зависимостей нет). Эмулятор работает с виртуальной файловой системой (VFS),
которая целиком хранится в памяти и загружается из ZIP-архива (или из
base64-текста такого архива). Содержимое архива на диск не распаковывается,
все изменения (`mkdir`) делаются только в памяти.

Структура репозитория:

| Путь | Назначение |
|------|------------|
| `src/emulator/` | исходный код эмулятора |
| `tests/` | модульные тесты (`unittest`) |
| `vfs/` | демонстрационные VFS в формате base64 (`minimal`, `files`, `deep`) |
| `startup/` | стартовые скрипты с командами эмулятора |
| `scripts/` | скрипты ОС, запускающие эмулятор для проверки каждого этапа |
| `tools/` | генератор демо-VFS и проверка правил оформления кода |
| `run.sh`, `run.bat`, `Makefile` | запуск, тесты, демо |

Модули `src/emulator/`:

- `parser.py` — разбор строки: слова, кавычки, раскрытие `$VAR` / `${VAR}`;
- `repl.py` — интерактивный цикл и выполнение строки с обработкой ошибок;
- `config.py` — параметры командной строки и отладочный вывод;
- `script.py` — стартовый скрипт;
- `vfs.py`, `vfs_loader.py` — VFS в памяти, загрузка из ZIP/base64;
- `shell.py` — состояние сессии (VFS, текущий каталог);
- `commands.py`, `cmd_*.py` — команды.

## 2. Функции и настройки

### Параметры командной строки

| Параметр | Описание |
|----------|----------|
| `--vfs PATH` | путь к физическому расположению VFS (ZIP или base64-текст ZIP). Без параметра используется VFS по умолчанию |
| `--script PATH` | стартовый скрипт. Команды выполняются по очереди, на экран выводятся и ввод (с приглашением), и вывод. Строки с ошибками пропускаются. Пустые строки и строки, начинающиеся с `#`, игнорируются. После скрипта (если в нём не было `exit`) начинается интерактивный режим |

При запуске эмулятор печатает отладочный вывод всех заданных параметров
(строки `[debug] ...`). Если файл VFS или скрипта не читается, эмулятор
сообщает об ошибке и завершается с кодом 1.

### Приглашение и парсер

Приглашение содержит имя VFS и текущий каталог: `deep:/docs/api$ `.
Имя VFS — имя файла без расширения (`default` для VFS по умолчанию).

Парсер поддерживает одинарные и двойные кавычки и раскрытие переменных
окружения реальной ОС: `$HOME`, `${HOME}`. В одинарных кавычках
переменные не раскрываются; неустановленная переменная раскрывается в
пустую строку. Незакрытая кавычка — ошибка разбора.

### Команды

| Команда | Описание |
|---------|----------|
| `ls [-l] [-a] [путь...]` | содержимое каталога. `-l` — длинный формат (тип, размер, имя), `-a` — показать `.`, `..` и скрытые файлы |
| `cd [путь]` | сменить каталог; без аргумента — корень VFS |
| `pwd` | текущий каталог |
| `tac файл...` | строки файла в обратном порядке |
| `tail [-n N] файл...` | последние N строк (по умолчанию 10); допустимы `-n N`, `-nN`, `-N`. Для нескольких файлов выводятся заголовки `==> имя <==` |
| `find [путь...] [-name шаблон] [-type f\|d]` | поиск; `-name` — glob-шаблон по имени, `-type` — файл или каталог. Без пути поиск идёт от текущего каталога |
| `mkdir [-p] каталог...` | создать каталог в памяти; `-p` создаёт недостающие родительские каталоги |
| `vfs-init` | заменить текущую VFS на VFS по умолчанию и сбросить её физическое расположение |
| `vfs-load путь` | загрузить новую VFS с диска (ZIP или base64); при ошибке текущая VFS не меняется |
| `exit` | выход |

Ошибки (`error: ...`) не завершают оболочку: неизвестная команда,
отсутствующий файл, неверный параметр, ошибка разбора и т. д.

Формат VFS: ZIP-архив либо base64-текст этого архива (для хранения в
репозитории без бинарных файлов). Демо-VFS в `vfs/` создаются командой
`make vfs` (`tools/make_vfs.py`):

- `minimal.b64` — один файл;
- `files.b64` — несколько файлов (в т. ч. пустой и с кириллицей);
- `deep.b64` — 3+ уровня каталогов, пустой каталог, бинарный файл.

## 3. Сборка, запуск и тесты

Сборка не нужна. Требуется Python 3.10 или новее.

```sh
./run.sh                                  # интерактивный режим
./run.sh --vfs vfs/deep.b64               # со своей VFS
./run.sh --vfs vfs/deep.b64 --script startup/stage4_commands.txt
run.bat --vfs vfs\deep.b64                # Windows

make test                                 # модульные тесты
make style                                # проверка правил оформления кода
make demo                                 # все скрипты из scripts/
```

Скрипты проверки этапов (`scripts/`):

| Скрипт | Что проверяет |
|--------|---------------|
| `stage2_*.sh` | параметры `--vfs`, `--script`, ошибки скрипта |
| `stage3_minimal.sh`, `stage3_files.sh`, `stage3_deep.sh` | три варианта VFS и `vfs-init` |
| `stage3_errors.sh` | повреждённая и отсутствующая VFS |
| `stage4_deep.sh`, `stage4_files.sh` | `ls`, `cd`, `tac`, `tail`, `find` |
| `stage5_mkdir.sh` | `mkdir`, `vfs-load` |
| `stage5_all.sh` | сквозная проверка всех команд |

## 4. Примеры использования

```text
$ ./run.sh --vfs vfs/deep.b64
deep:/$ ls
bin
docs
empty_dir
readme.txt
src
deep:/$ cd docs/api
deep:/docs/api$ find . -name 'spec*'
./v1/spec.txt
./v2/spec.txt
deep:/docs/api$ tail -n 1 v2/spec.txt
DELETE /d
deep:/docs/api$ tac v1/spec.txt
POST /b
GET /a
deep:/docs/api$ mkdir -p /tmp/work
deep:/docs/api$ ls -l /tmp
drwxr-xr-x        0 work
deep:/docs/api$ echo $HOME
error: echo: command not found
deep:/docs/api$ ls $HOME
error: ls: cannot access '/root': No such file or directory
deep:/docs/api$ vfs-init
default:/$ exit
```

Фрагмент вывода стартового скрипта (`./run.sh --vfs vfs/deep.b64 --script startup/stage_all.txt`):

```text
[debug] parameters:
[debug]   vfs    = vfs/deep.b64
[debug]   script = startup/stage_all.txt
deep:/$ ls -l /docs
drwxr-xr-x        0 api
-rw-r--r--       24 guide.txt
deep:/$ bad_command
error: bad_command: command not found
```
